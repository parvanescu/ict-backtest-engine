# UI

Part of [[00_architecture_overview]]. What it talks to: [[07_signals_and_ui]] (signals) and [[10_live_bars]] (bars). The project is `project/ui`.

## Stack

| Item | Choice |
|------|--------|
| App | React 19, TypeScript, Vite |
| Chart | TradingView `lightweight-charts` 5 (Apache-2.0): line series, markers, price lines |
| Components | Mantine 9 (layout, inputs, tables), dark theme |
| Service connection | `@stomp/stompjs`: one WebSocket for the whole UI; history over `fetch` |
| Tests | Vitest, on the pure logic in `src/lib` |

All versions are pinned exactly in `package.json`.

## The view

```
┌ Alert Service ──────────────────────────────────────────────────────── ● Live ┐
│ Rule: Sequence range sweep │ ES                    [Sweep event 10:12:40] │ NQ … │
│ Instruments [ES NQ YM RTY] │ O … H … L … C … 10:12:41                    │      │
│ (o) Run rule               │ ┌──────────────────────────────┐ REPORTS    │      │
│ SEQUENCE_RANGE_SWEEP[…]    │ │ 4 lines, ● Sweep event       │ 10:12:40   │      │
│ [Day valid]                │ │ - - 3-3-3 H / M / L          │ low 44168  │      │
│                            │ └──────────────────────────────┘ < 44180    │      │
│                            │ YM …                                  │ RTY …       │
└ Informational tool only, not financial advice ─────────────────────────────────┘
```

| Part | Shows |
|------|-------|
| Rule panel | The sequence range sweep only. Instruments (default ES, NQ, YM, RTY; at least two); the switch subscribes to the rule's topic, which starts it ([[05_rule_lifecycle]]); the canonical key; the day status |
| One panel per instrument | Laid out two per row on wide screens, one per row otherwise |
| Chart | The instrument's 1-second bars as four lines, updated with every bar: open (blue), high (green), low (red), close (amber); New York time on the axis. The legend shows the values under the crosshair, or the latest bar (refreshed at most 4 times a second) |
| Events on the chart | A `RANGE_SWEEP_EVENT` about the instrument is a neutral marker at the trigger second, the same for either side broken. It sits on the bar at or before its `eventTime`. The latest check result also shows in the panel header: "Sweep event at HH:MM:SS", or, for an instrument that was checked after a break and did not qualify (`RANGE_SWEEP_NO_EVENT`), an outlined "Checked, no event at HH:MM:SS". The reports window lists the no-event result as facts: who broke which side, and the instrument's bar outside `L` / `M` (low break) or `M` / `H` (high break). It has no chart marker and does not clear on its own; Stop/Start or a reconnect clears it with the other signals |
| Range lines | Dashed `3-3-3 H`, `M`, `L` from the latest event about the instrument |
| History shown | Buttons `1m`, `5m`, `30m`, `2h`, `All` above each chart. A preset keeps showing that span while bars stream in; `All` stays fitted to everything loaded. Charts start on `All`. Zooming (wheel, pinch) or panning by hand takes over, until a preset is chosen again or the chart is double-clicked (`All`). Bars can be drawn as narrow as 0.001 px, so a whole day (86,400 bars) fits when zoomed out |
| Reports window | Beside the chart: the instrument's `REPORT`s (its range breaks: time, side, price, level; and its sweep events: the trigger instrument, side and price, and the instrument's own low or high against its L, M, H), newest first, the last 200. A rolling window instead of chart markers, since while price stays beyond a level there is one report per second |
| Day status | An `INVALID_WINDOW` day shows a banner above the charts |

Charts show bars whether or not the rule runs; each chart is its own bar subscription on the one shared connection.

Labels stay factual ("Sweep event", "low 44168 < 44180"), never instructions or directions, as the README requires.

## Data flow

| Piece | Does |
|-------|------|
| `StompConnection` | One STOMP client; re-subscribes everything after a reconnect and counts connections (`epoch`) so data reloads after a gap |
| `useBarFeed` | Subscribes to `/topic/bars/{symbol}`, buffers, fetches `GET /api/bars`, merges by time, then streams into the chart. Bars go straight to the chart, not React state |
| `useSignals` | Subscribes to `/topic/signals/{ruleKey}`, fetches `GET /api/signals` (retrying briefly: the rule starts right after the subscription), merges by `id` |
| `src/lib` | Pure functions: bar conversion and merging, canonical rule key, markers, range levels, New York time formatting |

## Run it

In Docker Desktop: `cd project` then `docker compose up --build`, and open `http://localhost:5173` ([[09_build_and_run]]).

Without Docker, in three terminals:

```
cd project/system && ./gradlew bootRun          # the service, 127.0.0.1:8080
cd project/ui && npm install && npm run dev     # the UI, http://localhost:5173
cd project/system && ./gradlew demoAdapter      # synthetic market data
```

Open the UI. The rule runs by default (sequence range sweep on ES, NQ, YM and RTY); switch it off to change the instruments. The charts subscribe to the bars as soon as the page opens, so the demo adapter sees the subscriptions, waits 3 s for the rule, then plays 2026-10-12 from 09:44 New York (just before the 3-3-3 range opens) to the 17:00 close: 26,160 bars per instrument, about 7 minutes at the default speed of 60 simulated seconds per real second.

| NY time | Scripted | Event |
|---------|----------|--------|
| 10:12:40 | YM wicks below its 3-3-3 low and closes back at its mean; ES and RTY are in the lower half of their ranges, NQ in the upper half | Sweep events for ES and RTY |
| 10:20:15 | NQ wicks above its 3-3-3 high; YM is in the upper half of its range | Sweep event for YM (ES and RTY already have today's event) |

The rest of 3-3-4 stays inside the ranges; after 10:30 prices walk freely. The charts with an event get the marker and the range lines, and the trigger's reports window shows the break. The walk uses a fixed seed, so every run plays the same day. After the close the adapter stays idle; to play the day again restart both the service and the adapter (the service keeps the day's bars and rule state).

`npm test` runs the unit tests, `npm run build` type-checks and builds `dist/`. Another service address: copy `.env.example` to `.env.local`.
